# Tasquel UX Audit, Round 2 — 2026-10-25

This round re-checks both lists from 2026-10-24 (the Claude audit in `ux-audit-2026-10-24.md` and the 22-item Terminal audit) against the uncommitted changes in the working tree. It also reviews the new Smart Add feature (`ParsedTask.swift`, `AppleIntelligenceTaskParser.swift`). I read the code and diffs; I didn't build the app or run the tests.

## Summary

Every item on the Terminal list has been dealt with, and so have about half of the Claude audit's items. The changes introduce no new problems as serious as the old ones. Two Claude-audit items (iPad and iPhone landscape) are still undecided and matter for submission. Smart Add needs one change before launch: show sighted users what it added.

## Decided differently (fine, but worth a test)

- **Tapping a name renames it.** Sub-tasks now behave like tasks instead of the other way round, so the rule is consistent. The risk is the same as before: people who tap a row to tick it get a keyboard, and the check target is now just the small circle. Watch the first few people who use it.
  One wrinkle: in an open card, tapping the *category* name closes the card, while tapping a *task* name renames it. Names do two different things inside one card.
- **New tasks still start as One-Time.** Onboarding now says so, and Smart Add picks the mode from the words, which helps. Anyone who uses plain Return and skipped the tour will still lose unfinished tasks at the end of the week.

## New in this round

### N1. Smart Add doesn't show sighted users what it did (fix before launch)
VoiceOver users hear "Added Gym, repeating goal of 3". Everyone else gets a haptic and a task that appears with a possibly shortened title and different icons. If the model guessed wrong, nothing points that out, and there's no undo.
**Suggest:** a short message under the row for about 4 seconds: "Added *Gym* · repeating goal of 3 · Undo". `describe(_:)` already builds the text.

### N2. "Daily" becomes a once-a-week checkbox
`TaskTextHints` treats daily, every day and nightly as Repeating, and the result is a checkbox. "Meditate daily" then means one tick a week, which isn't what the person meant.
**Suggest:** treat daily habits as a repeating goal of 7, and "every weekday" as 5, the same way "3x per week" becomes a goal of 3. Update the model's examples to match.

### N3. Typed text is added however the keyboard closes
This matches Reminders, and it fixes the lost-input bug. But there's no way to back out of a half-typed task except deleting the text first. With no undo, one stray swipe leaves a junk task to delete, behind a confirmation dialog.
**Suggest:** no change if undo arrives (item 6). Otherwise, consider skipping the auto-add when the text is a single character.

### N4. The type and mode picker remembers differently
After Smart Add, the picker resets to Checkbox / One-Time. After Return, it keeps the last type and mode picked.
**Suggest:** pick one. Keeping the last pick is fine for Return; then Smart Add shouldn't reset it either. Or reset after both.

### N5. Smart Add is hard to discover
The sparkles button only appears after you start typing, and only on Apple Intelligence devices. It's in Help but not in the welcome tour.
**Suggest:** if it's a headline feature, mention it on the task-types page of onboarding ("Or type it in your own words and tap ✨"), shown only when `isAvailable`. It's also worth a line in your App Store description.
