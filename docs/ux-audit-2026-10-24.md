# Tasquel UX Audit — 2026-10-24

This audit covers what a person using the app experiences: first launch, daily use, editing, empty and error states, and launch-facing details. It comes from reading every view in `Tasquel/`, not from running a build, so check the visual items on a device. Data logic and accessibility were already audited on 2026-10-19 and aren't repeated here.

Each item names the file to change, so it can be handed to Claude Code as is.

---

## Fix before launch

### 1. Tapping a task's name renames it
`TaskRowCard.swift` ~L150: `Text(task.title)…onTapGesture { startEditingTitle() }`. The title is the biggest target in the row, and most people tap a task to check it off. Here the keyboard opens instead, on every card, outside edit mode. Sub-tasks only rename in edit mode (`SubTaskRowCard`), and categories only from the card's edit button, so tasks behave differently from everything else.
**Suggest:** rename tasks only while the card's edit button is on, like sub-tasks, and make a tap on the title toggle the checkbox (or do nothing). Update the Help line "Tap a task's name to rename it".

### 2. The keyboard closes after each new task
`AddTaskRowCard.addTask()` clears the field but doesn't put focus back, so Return closes the keyboard. Adding a week's tasks means tapping the field again for every one. Sub-tasks and list items already keep focus (`addSubtask()` sets `isSubtaskFieldFocused = true`).
**Suggest:** set `isFocused = true` after adding, use `.submitLabel(.next)`, and close the field when Return is pressed on an empty line, the same as sub-tasks.

### 3. The first screen is five empty cards
A new user finishes onboarding and lands on Errands, Work, Fitness, Study and Appointments. Each card shows "Completed: 0/0", a gray ring and a blank body. Nothing says what to do next. `CollapsedCategoryContent` draws nothing when `tasks` is empty.
**Suggest:** an empty card says "No tasks yet" with "Tap to add" in its place. Optionally, open the first card after onboarding with the Add Task field ready.

### 4. New tasks default to One-Time, but the app's pitch is carry-over
`AddTaskRowCard`: `@State private var newMode: TaskMode = .oneTime`, which the Help confirms ("New tasks start as One-Time"). The welcome animation and the onboarding copy sell unfinished tasks moving to next week. Someone who never opens the picker will see unfinished tasks disappear when the week ends, which is the opposite of what they were shown. The store's own default is already `.carryOver` (`addTask(…mode: TaskMode = .carryOver…)`).
**Suggest:** default to Carry Over, and update the Help line.

### 5. Past weeks give no feedback
In a past week, tapping a checkbox does nothing (`guard !isPastWeek else { return }`) and nothing says the week is read-only. The only clue is that the Edit button is gone. People will think the tap missed or the app is broken.
**Suggest:** show "Past week · view only" under the header or in place of Edit, and dim the checkboxes (or `.disabled(true)` them so VoiceOver says "dimmed").

### 6. iPad ships, but its layout isn't done
`TARGETED_DEVICE_FAMILY = "1,2"`, yet `CategoryGridLayout` is two columns at every width, and "iPad-specific layout optimizations" is still in the recap's to-do list. On a 13" iPad the cards are very wide, and App Review checks iPad builds.
**Decide:** use 3–4 columns at regular width (for example, columns = `max(2, Int(width / 280))`), or ship 1.0 for iPhone only (iPads can still run it in compatibility mode) and add iPad in 1.1. You'd need iPad screenshots either way if you keep iPad.

### 7. iPhone landscape is on, with known landscape problems
`UISupportedInterfaceOrientations_iPhone` includes both landscapes, and the recap lists "events panel in landscape" as a known issue. A weekly planner gets little from landscape on a phone.
**Suggest:** portrait only on iPhone for 1.0 (keep all orientations on iPad).

## Worth doing (medium)

### 8. Closed cards hide anything past five tasks
`CollapsedCategoryContent` uses `category.tasks.prefix(5)` and shows no overflow, so a card with 9 tasks looks like a card with 5.
**Suggest:** a "+4 more" line, or show the unfinished tasks first so the preview shows what's left.

### 9. Tasks can't be reordered or moved
The store has no move or reorder for tasks, only `setCategoryOrder` for cards. Reordering and "move to another category" are among the first things people try in a list app.
**Suggest:** drag handles on tasks while the card's edit button is on (cards already have a hold-to-drag pattern to match). "Move to…" can come later.

### 10. Confirmations instead of undo
Every delete asks first, including a single sub-task or list item. That's a lot of taps for small changes, and checking a task off by mistake has no undo either.
**Suggest:** keep the confirmation for deleting a category or a task with sub-tasks. Delete items and empty tasks straight away and show a short "Deleted · Undo" message (or support shake to undo with `UndoManager`).

### 11. Editing works three different ways
- The bottom bar's grid button (`square.grid.2x2`) is category management: add, delete, reorder. The icon reads like a layout switch, and the empty state's "Tap the grid button below" relies on people knowing that.
- Each card's pencil edits that card's tasks and its name.
- Task names rename with a single tap at any time (item 1).

**Suggest:** fixing item 1 removes the third. For the first, use a clearer icon or label (a "Categories" text label, or `rectangle.stack.badge.plus`), and give the empty state the same wording.

### 12. Adding a category takes an extra step every time
`AddCategorySheet`: after you pick or name a category, a dialog asks "Every Week / This Week Only". Most categories are every week.
**Suggest:** a "This week only" toggle in the sheet, off by default, so one tap adds the category.

### 13. Onboarding has no Skip and can't be replayed
There are five pages, `interactiveDismissDisabled()` is set, and there's no Skip button. The calendar page tells people to go to Settings rather than letting them turn the calendar on right there. Nothing in Settings or Help brings the tour back.
**Suggest:** Skip in the top-right corner. A "Connect Calendar" button on the calendar page that runs `requestAccess()` while the reason is on screen (with "Not now" as the main button). "Replay Welcome Tour" in Help. On the recap's open question: no extra closing page is needed once Skip exists.

### 14. Your name is the first setting but is never used
`Section("Name")` is the top of Settings, but `userName` isn't shown anywhere (recap item 14).
**Suggest:** remove it for 1.0 or use it, for example "Good morning, JB" above the week. A setting that does nothing makes the app feel unfinished.

### 15. Dates are US-only in two places
- `Week.displayTitle` is built by hand as `"Week of M/D/YY"`. In most other countries "Week of 10/5/26" reads as 10 May.
- `DatePickerSheet.formattedWeekStart` hard-codes `"MMM d, yyyy"`.

The bottom bar's date is already localized, so these are also inconsistent with it.
**Suggest:** `startDate.formatted(.dateTime.month(.abbreviated).day())` gives "Week of Oct 5", which is clearer everywhere.

### 16. Unchecking the last calendar checks them all again
`CalendarService.effectiveSelection` falls back to the default calendars when the saved selection is empty. Unchecking the last calendar makes the defaults come back.
**Suggest:** don't let the last selected calendar be unchecked, or allow none and show "No calendars selected" (and hide the bar's calendar button).

## Polish (low)

17. **Red rings at the start of every week.** `completionNone` is red, so on Monday morning every card is red. Red reads as failing or overdue. Use neutral gray for 0, orange for partly done and green for done.
18. **No haptics when you finish something.** The only haptics are for card dragging. Add `.sensoryFeedback(.success, …)` when a task, goal or list completes, and maybe a stronger one when a whole card completes.
19. **Done looks different for tasks and sub-tasks.** Sub-tasks are struck through and dimmed; tasks aren't (removed for contrast). Pick one treatment, for example a dimmed title with no strikethrough for both.
20. **Goals are slow to update.** Each update takes Add Progress, typing and Add. For quantity goals ("50 push-ups"), quick "+1" / "+5" buttons beside Add Progress would cover most updates.
21. **Changing weeks scrolls back to the top** (already noted in the recap). Small, but noticeable when moving between neighboring weeks.
22. **Deleting the app deletes everything.** There's no export or iCloud sync, which you found out first-hand. That's fine for 1.0, but add a line to the support page FAQ (data lives on the device and is included in iPhone backups) so support emails have an answer.

## Already in good shape
- Accessibility: 44pt touch targets, done states that don't rely on color, Reduce Motion, full-width cards at large text sizes, VoiceOver move actions.
- Error handling: the unreadable-data screen with Retry and a Start Fresh that never deletes the file; the save-failure alert.
- Destructive dialogs say exactly what will happen, including past-week history.
- Launch basics: the privacy policy and support pages at jbfentner.com/tasquel/… both load with a contact email; there's a privacy manifest, a clear calendar permission string, and the encryption flag is set.
- The Help guide is thorough and matches the app, apart from the lines named in items 1 and 4.

## Not gaps for 1.0
Widgets, reminders, iCloud sync and stats are already parked as later or paid ideas. Nobody will expect them from a first release.
